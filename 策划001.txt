这个思路可行，关键是让**一份结构化的场景描述（JSON）同时被智能体和人操作**。智能体不直接"画"3D，而是读写这份 JSON，导演在界面上拖动的也是同一份数据。

## 一、整体流程

1. **输入**：导演给出剧本或一段镜头描述。
2. **智能体生成初稿**：调用工具函数，生成场景、角色站位、走位路径和运镜，输出场景 JSON。
3. **浏览器渲染**：前端读取 JSON，用 3D 引擎显示出来。
4. **导演微调**：拖动角色和机位，改关键帧、时长、焦距，改动写回 JSON。
5. **导出参考素材**：按固定帧率逐帧渲染，输出参考视频、首帧图、关键帧图。
6. **喂给视频模型**：智能体根据 JSON 自动生成提示词，连同参考素材调用视频模型。
7. **检查与迭代**：智能体看生成结果，判断站位和运镜是否偏离，提出修改建议，回到第 2 步或第 4 步。

## 二、场景描述格式（核心）

```json
{
  "scene": { "preset": "room_small", "size": [8, 3, 6] },
  "actors": [
    { "id": "A", "label": "男主", "color": "#e74c3c",
      "start": [-2, 0, 1], "facing": [1, 0, 0], "pose": "stand",
      "moves": [{ "to": [1, 0, 0], "t0": 1.0, "t1": 3.0, "pose": "walk" }] },
    { "id": "B", "label": "女主", "color": "#3498db",
      "start": [2, 0, 0], "pose": "sit" }
  ],
  "camera": {
    "fov": 35,
    "keyframes": [
      { "t": 0, "pos": [0, 1.6, 6], "lookAt": "A" },
      { "t": 4, "pos": [0, 1.5, 3], "lookAt": "B", "ease": "inOut" }
    ]
  },
  "duration": 5, "fps": 24, "aspect": "16:9"
}
```

几点设计建议：

- 用**语义标签**（`lookAt: "A"`）而不是纯坐标，角色移动后镜头仍然跟得上。
- 坐标单位统一用米，朝向统一约定，否则智能体很容易搞混。
- 版本化保存，每次修改存一份，方便撤销和对比。

## 三、智能体怎么接入

大模型的空间推理不擅长直接吐精确坐标，所以不要让它写原始数值，而是给它**高层工具**，由你的代码把工具调用翻译成坐标：

- `add_actor(label, position_hint)`：位置提示用"画面左侧""桌子对面"这类描述。
- `arrange(actors, layout)`：布局预设，如对峙、并排、三角站位，由代码计算具体坐标。
- `move_actor(id, path, t0, t1)`。
- `camera_move(type, target, t0, t1)`：type 取推、拉、摇、移、环绕、跟拍、升降等预设，代码生成关键帧。
- `set_shot(size)`：景别（全景、中景、特写），代码根据目标和焦距反推机位距离。

再加一个**自检回路**：让前端渲染几张关键帧截图发回给多模态模型，让它判断"人物是否入画、有没有遮挡、构图是否合理"，不合格就自己修正。这一步对质量提升很明显。

## 四、前端技术选型

- **渲染与交互**：Three.js，配合 React Three Fiber。自带 TransformControls，可直接拖拽移动、旋转、缩放。
- **角色**：用 glTF/VRM 人形模型，配 Mixamo 一类的动画库（站、坐、走、跑）。先用素模，不必追求精细。
- **时间轴**：自己做关键帧轨道，摄像机轨迹用 CatmullRom 样条加缓动函数。
- **状态管理**：以场景 JSON 为唯一数据源（Zustand 之类即可），撤销重做基本免费。
- **导出视频**：建议用**逐帧离线渲染**，不要实时录屏。用 WebCodecs 的 VideoEncoder 加 mp4 封装库，或 `canvas.captureStream` + MediaRecorder 作为简易方案。逐帧渲染的好处是帧率稳定、不会因为电脑卡顿掉帧。

## 五、参考视频怎么做才对模型有用

这是最容易被忽略的一环，建议同时导出几种素材：

- **素模视频**：每个角色用**不同的纯色**，便于模型区分；背景保持干净。
- **首帧图和关键帧图**：适合图生视频、首尾帧类模型。
- **可选的辅助图**：深度图、分割图、骨架图。这些对支持控制信号的模型或工作流（如 ComfyUI 里的 ControlNet 类方案）有用，可以后续再加。
- **自动生成的提示词**：从 JSON 直接翻译出来，例如"红色角色 A 从画面左侧走向中央，镜头缓慢推近女主"。并在提示词里写明颜色和角色的对应关系。

有一点要提前确认：**不同视频模型对"参考视频"的支持差别很大**。有的能把它当作运镜或动作参考，有的只接受首帧加文字。所以导出层要做成可配置的，按目标模型选择输出哪些素材，选型前建议先拿几个目标模型用简单素模视频实际测一下效果。

## 六、MVP 路线

1. 先做一个能摆素模、拖拽、建一个机位并导出首帧图的最小编辑器。
2. 加关键帧时间轴和摄像机运动，能导出 mp4。
3. 定下场景 JSON 格式，接入智能体，先只支持"布局加运镜预设"。
4. 加截图自检回路，以及提示词自动生成。
5. 对接视频模型 API，形成闭环。
6. 再考虑多镜头、共享场景、辅助控制图。

## 七、几个要预先想到的坑

- 视频模型不会严格遵循参考，素模与最终画风差距大时尤其明显，所以要让智能体在结果偏离时能给出调整建议，而不是默认一次成功。
- 模型单段时长有限，需要按镜头拆分，多镜头之间靠共享同一个场景和角色设定保持一致。
- 智能体生成的路径可能穿墙、穿模，需要加简单的碰撞和边界检查。
